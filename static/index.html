What happens inside

1. Read the file

Filetape reads every byte and notes the name. If it's an image, it also reads the pixels and the colour profile.

2. Race the methods

Images race JPEG XL, prediction errors and the file as it is. Any other file is compressed with LZMA, or stored as it is if that's smaller.

3. Bytes become sound

Every two bytes of the winner become one 16-bit audio sample. Good compression looks random, so this sounds like loud white noise.

4. Press the tape

FLAC is the carrier, adding about 0.2%. Filetape decodes the result and compares it with your file before it hands you anything.

Measured, and every file came back exact

What shrinks, and by how much

Text and code shrink most. On 23 sample images the total dropped by 30.8%. Files that are already compressed, like zips, MP3s and videos, don't shrink and grow slightly.

  • Colour PNG, with logos
    27–59% smaller
  • Greyscale PNG
    6–45% smaller
  • JPEG
    13–22% smaller
  • Text and code
    64–78% smaller
  • Programs
    About 71% smaller
  • One PDF
    About 11% smaller
  • One zip
    0.6% larger
Batch

Whole folders fit on one tape

Zip a folder and drop it in. You get a new zip with the same folders, and uploading that zip turns everything back. Every file inside gets the same treatment, and anything that wouldn't shrink is copied unchanged.

In one test, 10 files went from 27.2 MB to 18.8 MB, and all 10 came back with the same names.

Warning

One lossy step and the file is gone

Keep the audio in FLAC or WAV. MP3, AAC or re-recording it changes the samples, and the checksum refuses the file. Drag the slider to see why.
